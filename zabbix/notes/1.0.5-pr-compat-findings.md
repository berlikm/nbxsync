## 4. Trigger-dep deep dive

Source: `1.0.5:nbxsync/utils/trigger_dependency_sync.py` and `1.0.5:nbxsync/jobs/synchost.py` (105 lines). all-in-one `synchost.py` is 300 lines and has **no** import of this module.

### 4.1 #115 — inherited-only hosts no-op **even before** bindings

**Proved.**

`get_server_assignments(device)`:

```python
ZabbixServerAssignment.objects.filter(
    assigned_object_type=object_ct,
    assigned_object_id=device.pk,
    sync_enabled=True,
    zabbixserver__sync_enabled=True,
)
```

#115 `SyncHostJob.run()`:

```python
all_objects = get_assigned_zabbixobjects(self.instance)
zabbixserver_assignments = all_objects.get('server_assignments', [])
```

That list includes Site/SiteGroup/Region/Role rows. Inherited copies are detached (`pk=None`, `_is_inherited_copy`) so hostid is not written back to the Site row.

On a pure inherited fleet:

1. HostSync **does** create/update the Zabbix host (#115).
2. There is **no** `ZabbixServerAssignment` with `assigned_object_id=device.pk`.
3. `get_server_assignments` → `[]` → `get_host_assignments` → `{}`.
4. `_prepare_child_dependency_sync` logs `No Zabbix host assignment with hostid found for %s.` and returns `[]`.

1.0.5 stock is internally consistent: its `SyncHostJob` also only queries device-level assignments, so inherited-only hosts were never synced and never needed trigger-dep. Combining **#115 + stock #100** is the incompatibility.

Upstream test locks this in:

`test_get_server_assignments_filters_and_selects_server` asserts the filter is `assigned_object_id=42` (the device pk).

### 4.2 #125 — hostid cleared on the assignment; skip everyone; silent

**Proved.** After `HostSync.sync()`:

```python
def _clear_direct_hostid(self):
    if not self._should_persist():  # inherited copy: skip
        return
    ...
    self.obj.hostid = None
    self.obj.save(update_fields=['hostid'])
```

Test `test_direct_assignment_hostid_migrates_to_binding` asserts `assignment.hostid is None` and the binding holds the id.

Trigger-dep always **re-queries** the DB (`get_server_assignments`); it does not use the in-memory assignment from the synchost loop. After #125:

- Direct assignment row exists, `hostid` is NULL → `if not assignment.hostid: continue` → empty map → same warning → `[]`.
- Inherited-only: still no device row (#115) → same empty map, even if a `ZabbixHostBinding` exists.

**Silent vs crash:** no crash. `_sync_child_dependencies` catches per-child and per-server exceptions. The synchost hook catches everything:

```python
try:
    sync_device_trigger_dependencies(self.instance)
except Exception:
    logger.exception('Trigger dependency sync failed for %s; continuing.', self.instance)
```

HostSync still succeeds. Enabling the flag on all-in-one after a naive cherry-pick will **not** break polling; it will **not** write dependencies.

### 4.3 #117 — trigger **names** come from templates TemplateRule attaches

`get_host_trigger` is an exact Zabbix `description` filter (`expandDescription=True`). One `trigger_description` per **level**, not per platform.

TemplateRule (`get_assigned_zabbixobjects` regex loop) decides which template (hence which ICMP trigger **name**) lands on the host. If EXOS stock ICMP ≠ VOSS `Extreme VOSS: Unavailable by ICMP ping` ≠ IQ Engine `Extreme IQ Engine: Unavailable by ICMP ping`, a single `trigger_description` cannot match both. Config must either:

- use one ICMP name everywhere (not true of stock Extreme templates), or
- give up on mixed-platform levels, or
- (out of scope for #100) key off something other than a static name.

Role matching for TemplateRule (`role_pattern` regex on role **name**) is independent of trigger-dep role **tokens**. Both can be right while the other is wrong.

### 4.5 Hook placement (105-line 1.0.5 vs ~300-line ours)

1.0.5 `SyncHostJob.run()`:

```text
for assignment in device-level assignments:
    if not sync_enabled: continue          # da7c122; keep
    if DELETED: delete else: sync
    if device and not DELETED and enabled:
        try: sync_device_trigger_dependencies(instance)
        except: log and continue host job
```

Ours: inherited assignments, exclude_tag early return, binding retirement, partial errors, OOB interface filtering, **no hook**.

**Where the hook must go so we do not drop 1.0.5 behaviour:**

1. Import `sync_device_trigger_dependencies`.
2. Call it **once** after the assignment `for` loop has finished successful HostSync work, **before** `_raise_on_partial_failure()` (a failed interface should not skip dep sync; a failed dep sync must not fail the host job — wrap in try/except like 1.0.5).
3. **Do not** call it on the exclude_tag return path.
4. **Do not** call it when `zabbix_status == DELETED`.
5. **Do not** call it for VMs (`model_name != 'device'`).
6. Do **not** paste it inside the per-assignment loop on our job: we may have N inherited+direct servers; once after all servers is enough (idempotent anyway). 1.0.5-in-loop is acceptable but redundant.
7. Keep `continue` (never `return`) for `sync_enabled=False`.
8. Keep 1.0.5 logging on the initial HostSync swallow (we already log; 1.0.5 `pass`ed).

Without (1)+(2), rebasing the stack onto 1.0.5 **drops the feature** even if `settings.py` gains `trigger_dependencies`. Upstream `test_run_syncs_trigger_dependencies_when_enabled` would fail on our synchost until the hook exists.

### 4.6 Can it **work** with our stack if we adapt it?

**Yes**, for closet-kill **ICMP → ICMP** (AP unavailable → switch unavailable → gateway unavailable), **if** hostid + inherited hosts + roles + cables + trigger **names** are fixed. It is alert correlation, not poller load.

**Adapter (specify, do not implement):**

1. **`get_host_assignments` / `get_server_assignments`:** resolve `(device, zabbixserver) → hostid` from `ZabbixHostBinding` (`get_host_binding` / `iter_host_bindings`). Fall back to assignment.hostid for unmigrated rows. Do **not** require a device-level `ZabbixServerAssignment`.
2. **Inherited hosts:** iterate servers from bindings, or from `get_assigned_zabbixobjects(device)['server_assignments']` (dedupe by `zabbixserver_id`), then look up hostid via (1). Same for parents.
3. **Hook:** §4.5.
4. **Settings coexistence:** merge 1.0.5 `TriggerDependencyConfig` + `7c0b534` validators into `PluginSettingsModel` **alongside** `exclude_tag` (default `''`), `allow_inherited_deletion` (default `False`), `adopt_existing_hosts` (default `False`). Keep `#115` `inheritance_chain` Site/Region paths. Do not reset `backgroundsync.interval` 360 → 60 unless intended (`#115` changed the default).
5. **Hostinfo (default-on, same hostid bug):** `_server_assignments_for` must use bindings (and inherited servers), not `assignment.hostid` on device-level rows. Keep 1.0.5’s outer `event_list` / `fetch_errors`.
6. **HostInterfaceSync extra_args:** pass `get_host_binding(instance, server).hostid` (or the in-memory hostid **before** `_clear_direct_hostid`), not `assignment.hostid` after clear. Optionally call `_resolve_binding()` at the start of `check_default_hostinterface` / `verify_hostinterfaces`.
7. **Role tokens:** add full names/slugs (`access point`, `switch access`, `switch dist`, `switch core`, …). Default `switch` ≠ `Switch Access`.
8. **Trigger names:** set `trigger_description` to the **actual** template trigger name on that level. Mixed EXOS/VOSS/IQ Engine cannot share one string.

**What it still cannot do:**

- **AP ICMP → that switch’s `UP-` LLD link-down.** #100 matches one static name per level, not per-port LLD (`Interface …(): Link down` / Extreme `UP-…`). Closet-kill (AP ICMP → switch ICMP) is in scope; port-level suppression is not.
- Incomplete `_path`, cross-server parents, VMs, unmatched roles, wrong trigger names — all skip with warnings.
