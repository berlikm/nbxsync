## Trigger dependency sync — behaviour to verify

Do not trust this block; re-read the module.

- After successful **device** HostSync, if `trigger_dependencies.enabled`.
- Classify device by **role name/slug token set intersection** (case-insensitive; hyphen/space variants). **Not substring:** `switch` does **not** match `Switch Access`.
- Default levels: AP → switch → gateway/firewall. Default trigger **names**: `AP status` / `Switch status` / `Gateway status`.
- Parents = cabled neighbors (`Interface._path` complete) with a **higher** level index. Cable direction ignored.
- `trigger.get(filter={'description': name})` — Zabbix API `description` = trigger **name**. Exact match. `expandDescription=True`.
- Host lookup: `ZabbixServerAssignment` where `assigned_object` **is that device** and `hostid` is set. Skip if empty.
- Same Zabbix server only. Multi-parent: child depends on all found parent triggers (Zabbix: suppress child if **any** parent is PROBLEM).
- Preserves unmanaged dependencies (CPU→ICMP etc.). Idempotent if ids already match.
- Syncing a parent also updates connected children (one switch → N APs).
- Hook on 1.0.5 sits **inside** the assignment `for` loop (would run once per server assignment; should be idempotent). Our rewritten `SyncHostJob` must not drop the hook; place it **once** after a successful final HostSync, and not on exclude-tag / deleted / VM paths.

**This is alert correlation, not poller load.** It does not stop SNMP timeouts.

## Our features that change identity / sync (must trace)

### #115 — inheritance

- Server / CG / macros / templates inherited from Site, SiteGroup, Region, Role, … Device often has **no row** `ZabbixServerAssignment(assigned_object=device)`.
- `SyncHostJob` detaches inherited assignments (`pk=None`, `_is_inherited_copy`) so hostid is not written back to the Site/Role row.
- **Hypothesis to prove or disprove:** #100 `get_server_assignments(device)` only queries `assigned_object_id=device.pk`. On a pure inherited fleet, that list is empty → trigger-dep **no-ops even without #125**. This may be the larger incompatibility than bindings.

### #125 — `ZabbixHostBinding`

- Durable `(object, zabbixserver) → hostid`. After sync, **clears** `ZabbixServerAssignment.hostid` on persisted direct assignments (`_clear_direct_hostid`).
- MaintenanceSync in #125 already reads bindings first, then legacy hostid.
- Delete path / `exclude_tag` / `allow_inherited_deletion` / `adopt_existing_hosts` go through bindings.
- **Hypothesis:** after #125, #100’s `if not assignment.hostid: continue` skips every host. Silent. HostSync still works.
- **Also verify:** `nbxsync/views/hostinfo.py` in #125 still uses `assignment.hostid` → Ops problems/events modal empty. 1.0.5 improved this view for multi-server; merging #125 without adapting hostinfo regresses a **default-on** UI, not only an optional flag.
- **Also verify HostInterfaceSync:** first `HostSync.sync()` may clear in-memory `assignment.hostid` before `extra_args={'hostid': assignment.hostid}`. Inherited copies skip `_clear_direct_hostid` (`_should_persist` false) so the common zero-touch path may be fine; **direct** device assignments may not. Confirm with tests / code order in `synchost.py`.

### #117 — TemplateRule

- Decides which templates (hence trigger **names**) land on a host. No hostid store. Compatibility = trigger-name config must match whatever TemplateRule attached, and EXOS vs VOSS cannot share one `trigger_description` unless names are identical.
- Rebase noise: `settings.py`, changelog, `inheritance.py`, query counts.

### #110 — render / preview

- Jinja context for tags/hostgroups. Unrelated to trigger objects. Rebase only.

### #129 — `use_oob_ip`

- Interface IP resolution. Does not change cabling or triggers. 1.0.5 also touched `zabbixhostinterface` forms (typos, gettext). Mechanical conflict.
